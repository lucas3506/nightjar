03 What it catches

Four ways a job goes wrong. One line catches all four.

Uptime monitors check if a server answers. Nightjar checks if the work happened: on time, successfully, and in a reasonable amount of time.

A Missedno ping

It didn't run at all

Reboots, edited crontabs, a disabled scheduler. Nothing to log, because nothing happened.

B Failedexit 1

It ran and broke

Report the exit code and POST the output. The tail of stderr arrives inside the alert.

C Slow PRO> max

It ran three times longer than usual

Ping /start first and every run is timed. Go over the limit and you get a warning.

D Stuck PROno finish

It started and never finished

A deadlock, a hung request, a lock never released. You know while it's still happening.

05 Setup

If it can make an HTTP request, it can check in.

No agent, no SDK, no sidecar. One request at the end of the job, a second one at the start if you want timings. The highlighted line is the only change.

08 Questions

Fair questions.

More in the FAQ and the docs, or ask a person.

How does heartbeat monitoring work?

Each check gets a unique URL. Your job requests that URL when it finishes. Nightjar knows the schedule, so when a request doesn't arrive on time (plus a grace period you choose), the check goes down and you get an alert.

It catches the failures that log-based monitoring misses: the server was off, the crontab was overwritten, the container never started, or the job hung forever.

What does setup actually involve?

Create a check, copy its URL, and append one curl (or fetch, or wget) call to your job. There's no agent to install, no SDK, and nothing to run on your servers.

Can it tell me why a job failed?

Yes. Ping /fail or /<exit-code> and POST the job's output. Nightjar stores the tail of that output and includes it in the alert, so the Slack or Discord message already contains the error.

Which schedules are supported?

Simple periods (every 5 minutes, every 6 hours, every day) and standard 5-field cron expressions evaluated in any IANA time zone, so DST changes don't produce false alarms.

Where do alerts go?

Slack, Discord, Telegram, Google Chat, ntfy (push notifications to your phone, no account needed), and generic webhooks with an optional shared secret. Every channel can be tested from the dashboard.

What happens when I hit my plan's limit?

You can't add checks past the limit, and nothing already running is touched. If you downgrade, the newest checks over the limit are paused, not deleted, and come back when you upgrade again.
