Monitor Kubernetes CronJobs

A Kubernetes CronJob can fail in ways that never surface as a failed pod: the controller misses its schedule (startingDeadlineSeconds), concurrencyPolicy: Forbid skips runs while an old one hangs, the image can’t be pulled, or someone suspends the CronJob and forgets. Pinging from inside the job catches all of these.

Store the URL as a secret

kubectl create secret generic nightjar --from-literal=url=https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN

Ping from the container

apiVersion: batch/v1
kind: CronJob
metadata:
  name: invoice-run
spec:
  schedule: "0 * * * *"
  timeZone: "Etc/UTC"
  concurrencyPolicy: Forbid
  jobTemplate:
    spec:
      backoffLimit: 0
      template:
        spec:
          restartPolicy: Never
          containers:
            - name: run
              image: ghcr.io/acme/invoices:1.8
              env:
                - name: NIGHTJAR_URL
                  valueFrom: { secretKeyRef: { name: nightjar, key: url } }
              command: ["/bin/sh", "-c"]
              args:
                - |
                  wget -qO- "$NIGHTJAR_URL/start" >/dev/null
                  node run.js; code=$?
                  wget -qO- "$NIGHTJAR_URL/$code" >/dev/null
                  exit $code

Create the Nightjar check with the same schedule and time zone as spec.schedule / spec.timeZone. On Pro, set a maximum duration a little above activeDeadlineSeconds to be told about runs that hang.
