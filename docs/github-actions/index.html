Monitor GitHub Actions schedules

GitHub Actions schedule triggers are convenient, but they fail quietly:

  • In public repositories, scheduled workflows are disabled automatically after 60 days without repository activity. GitHub sends an email, but no failed run ever appears.
  • Scheduled runs can be delayed or dropped during periods of high load, especially at the top of the hour.
  • A workflow that fails sends a notification only to whoever last edited the schedule.

Setup

  1. Create a Nightjar check with the workflow’s cron expression and the time zone UTC (Actions schedules are always UTC). Give it a generous grace period (30–60 minutes) because start times drift.
  2. Add the ping URL as a repository secret named NIGHTJAR_URL.
  3. Ping at the start and the end:
name: nightly-report
on:
  schedule:
    - cron: "17 6 * * *"   # avoid :00, it's the busiest minute
  workflow_dispatch:
jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - run: curl -fsS -m 10 --retry 5 "${{ secrets.NIGHTJAR_URL }}/start"
      - uses: actions/checkout@v4
      - run: ./scripts/nightly-report.sh
      - if: success()
        run: curl -fsS -m 10 --retry 5 "${{ secrets.NIGHTJAR_URL }}"
      - if: failure()
        run: curl -fsS -m 10 --retry 5 "${{ secrets.NIGHTJAR_URL }}/fail"

If the workflow gets disabled, no ping arrives and Nightjar marks the check down at the next expected time.
