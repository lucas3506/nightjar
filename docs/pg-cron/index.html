Monitor Supabase pg_cron jobs

pg_cron records each run in cron.job_run_details, but nothing tells you when a job starts failing, or stops being scheduled because the project was paused or the job was unscheduled. Ending each job with a ping fixes that.

Requirements

Enable the pg_cron and pg_net extensions (Supabase: Database → Extensions).

Ping after the work

select cron.schedule(
  'nightly-rollup',
  '30 1 * * *',
  $$
    select refresh_daily_rollups();
    select net.http_get('https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN');
  $$
);

The statements run in order within one job. If refresh_daily_rollups() raises an error, the job aborts before the ping, so Nightjar sees a missed run.

Report failures with the error message

Wrap the work in a function that catches the error and reports it:

create or replace function run_with_nightjar(token text, job text) returns void
language plpgsql as $fn$
declare url text := 'https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/' || token;
begin
  perform net.http_get(url || '/start');
  execute job;
  perform net.http_get(url);
exception when others then
  perform net.http_post(url || '/fail', jsonb_build_object('error', sqlerrm, 'state', sqlstate));
end $fn$;

select cron.schedule('nightly-rollup', '30 1 * * *',
  $$ select run_with_nightjar('YOUR_TOKEN', 'select refresh_daily_rollups()') $$);

pg_cron uses UTC unless cron.timezone is set, so create the Nightjar check in UTC.
