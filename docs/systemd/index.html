Monitor systemd timers

systemd gives you hooks for every stage of a run, so you can report start, success and failure without touching the script itself.

# /etc/systemd/system/backup.service
[Unit]
Description=Nightly backup
OnFailure=backup-failed.service

[Service]
Type=oneshot
Environment=NIGHTJAR_URL=https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN
ExecStartPre=-/usr/bin/curl -fsS -m 10 --retry 5 -o /dev/null ${NIGHTJAR_URL}/start
ExecStart=/opt/scripts/backup.sh
ExecStartPost=/usr/bin/curl -fsS -m 10 --retry 5 -o /dev/null ${NIGHTJAR_URL}

# /etc/systemd/system/backup-failed.service
[Service]
Type=oneshot
ExecStart=/bin/sh -c 'journalctl -u backup.service -n 80 --no-pager | curl -fsS -m 10 --retry 5 --data-binary @- https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN/fail'

# /etc/systemd/system/backup.timer
[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true

[Install]
WantedBy=timers.target

The - prefix on ExecStartPre means a failed start ping won’t block the backup. The failure unit sends the last 80 journal lines, which appear in the alert.
