Quick start

Nightjar works like a dead man’s switch. Each check has a schedule and a unique ping URL. Your job requests that URL every time it finishes. If a request doesn’t arrive when expected (plus a grace period), Nightjar marks the check down and alerts you.

1. Create a check

Create a free account and press New check. Give it a name and a schedule:

  • Period: “every 1 hour” — the next ping is due one hour after the last one.
  • Cron: 0 2 * * * in Europe/Berlin — the next ping is due at the next 02:00 Berlin time.

Choose a grace period: how late a ping may be before it counts as missed. Five to fifteen minutes suits most jobs.

2. Ping it

Copy the ping URL from the check page and call it when the job succeeds:

/opt/scripts/backup.sh && curl -fsS -m 10 --retry 5 -o /dev/null https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN
  • && means the ping is only sent when the script exits with status 0.
  • -fsS makes curl quiet but still print errors, and fail on HTTP errors.
  • -m 10 --retry 5 keeps a network blip from hanging your job or losing the ping.

The check page updates as soon as the first ping arrives, and its status changes from waiting to up.

3. Add an alert channel

Open Alert channels and add Slack, Discord, Telegram, Google Chat, ntfy or a webhook. Press Send test to confirm it works. Every enabled channel receives alerts for all of your checks.

4. Go further

  • Report failures explicitly with /fail or the exit code: Ping API
  • Measure duration and catch hung jobs with /start: Ping API
  • Attach the job’s output so it shows up in the alert: crontab guide
Tip: start with the job you'd least like to find out about a week late, which is usually the database backup.
