Product

A small tool that does one job properly.

Nightjar watches the clock for every scheduled task you have, and speaks up only when one of them misses its slot, breaks, drags, or hangs.

Start free → Read the docs

Detection

Missed runs

Every check knows when its next ping is due. If it doesn't arrive within the grace period, the check goes down.

Reported failures

Ping /fail or /<exit-code>. Any non-zero exit status marks the run as failed and alerts immediately.

Slow runs

Send /start before the work and Nightjar measures the run. Set a maximum duration to be warned when it is exceeded. Pro and Scale.

Stuck runs

A run that started but hasn't finished within its maximum duration triggers an alert while it is still hanging. Pro and Scale.

Recovery notices

When a failing or late check pings successfully again, every channel is told how long it was down.

Grace periods

From one minute to seven days, so a busy night doesn't page anyone for a backup that's eight minutes late.

Schedules

Simple periods

Every 5 minutes, every 6 hours, once a day, once a week, up to 31 days.

Cron expressions

Standard 5-field syntax, previewed in plain English as you type, with the next run times shown before you save.

Time zones

Cron schedules are evaluated in any IANA time zone, so daylight-saving changes don't create false alarms.

Context

Log excerpts

POST the job's output with the ping. The tail is stored with the run and included in failure alerts.

Run history

Every ping, failure, and state change, with duration, exit code, source IP and user agent.

Daily run chart

Thirty days of successes, failures and incidents per check, and the average duration for each day.

Alerts

Slack, Discord, Google Chat

Incoming webhooks, formatted for each app, with a link back to the check.

Telegram

Use your own bot token and chat ID. Messages go straight from Nightjar to Telegram.

ntfy push

Push notifications to your phone through ntfy.sh or your own ntfy server, with no account required.

Webhooks

A JSON payload for anything else, such as PagerDuty, Opsgenie, or your own incident tooling, with an optional shared-secret header.

Test sends

Send a test alert to any channel from the dashboard and see the delivery status code.

Delivery log

Every alert Nightjar tried to send, and what the receiving service answered.

Operations

Pause and resume

Silence a check during maintenance without losing its history or its URL.

Rotate ping URLs

Generate a new token if a URL leaks into a public log. The old one stops working immediately.

Status badges

An SVG badge for your README or internal wiki that shows whether a job is passing. Pro and Scale.

# m h dom mon dow  command
0 2 * * *  /opt/scripts/backup.sh && curl -fsS -m 10 --retry 5 -o /dev/null https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN

Ping only when the job exits 0. -f makes curl fail on HTTP errors, --retry rides out network blips.

#!/usr/bin/env bash
URL=https://wzbetaadovfmwgqfspcw.supabase.co/functions/v1/ping/YOUR_TOKEN
curl -fsS -m 10 --retry 5 -o /dev/null "$URL/start"
OUTPUT=$(/opt/scripts/backup.sh 2>&1); STATUS=$?
echo "$OUTPUT" | tail -n 100 | curl -fsS -m 10 --retry 5 -o /dev/null --data-binary @- "$URL/$STATUS"

on:

jobs:

    runs-on: ubuntu-latest
    steps:
      - run: curl -fsS -m 10 --retry 5 "${{ secrets.NIGHTJAR_URL }}/start"
      - run: ./scripts/nightly-report.sh
      - if: success()
        run: curl -fsS -m 10 --retry 5 "${{ secrets.NIGHTJAR_URL }}"
      - if: failure()
        run: curl -fsS -m 10 --retry 5 "${{ secrets.NIGHTJAR_URL }}/fail"

await fetch(`${URL}/start`);

  await syncStripeInvoices();

} catch (err) {
  await fetch(`${URL}/fail`, { method: "POST", body: String(err?.stack ?? err) });
  throw err;
}

    ping()
